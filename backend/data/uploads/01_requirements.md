# Office OS - 要件定義書

## 1. プロジェクト概要

### 1.1 プロジェクト名
**Office OS** - 統合オフィス管理プラットフォーム

### 1.2 ビジョン
サービスカタログ・チケット管理・来客管理・施設予約・ナレッジ・イベント管理・フロアマップなど、オフィス業務に必要な機能を統合的に提供するSaaSプラットフォーム。
管理者が業務フローを定義し、社内メンバーが利用し、エージェントが処理・管理する。将来的にはAIエージェントとの連携ハブとなる。

## 2. ユーザーと役割

### 2.1 3モードアーキテクチャ

| モード | ルート | 対象 | 概要 |
|--------|--------|------|------|
| 申請モード | `(requester)/` | 社内メンバー | カタログ閲覧・申請・ナレッジ閲覧・施設予約・イベント参加 |
| 対応モード | `agent/` | エージェント | チケット処理・承認・来客対応・ナレッジ管理・イベント運営 |
| 管理モード | `admin/` | 管理者 | カタログ設定・組織管理・マスタ管理 |

### 2.2 ロール定義

| ロール | 説明 | 認証方法 |
|--------|------|----------|
| **SystemAdmin** | システム全体の管理者。テナント作成、システム設定 | Google Workspace |
| **Admin** | テナントの管理者。カタログ設定、メンバー管理、組織設定 | Google Workspace |
| **Agent** | 処理担当者。チケット対応・来客管理・ナレッジ管理・イベント運営 | Google Workspace |
| **Approver** | 承認者。承認フローで承認/却下を行う（Agentと兼任可） | Google Workspace |
| **Requester** | 社内メンバー。カタログ申請・ナレッジ閲覧・施設予約・イベント参加 | Google Workspace |
| **APIClient** | 外部システム（CLI/MCP/AIエージェント） | APIキー |

### 2.3 マルチテナント構成

```
SystemAdmin (Office OS 運営)
  ├── Tenant A (企業A)
  │     ├── Admin
  │     ├── Agent (複数) ── 一部が Approver 兼任
  │     └── Requester (複数)
  ├── Tenant B (企業B)
  │     ├── Admin
  │     ├── Agent (複数)
  │     └── Requester (複数)
  └── ...
```

- テナント間のデータは完全に分離
- 1ユーザーは複数テナントに所属可能
- 1ユーザーは複数ロールを兼任可能

## 4. 非機能要件

### 4.1 認証・セキュリティ

| 項目 | 要件 |
|------|------|
| 認証 | Google Workspace OAuth 2.0 (OIDC) |
| 認可 | RBAC（ロールベースアクセス制御）+ 権限階層 |
| データ分離 | テナント間の完全なデータ分離 |
| 通信 | HTTPS必須 |
| APIキー | SHA-256ハッシュ保存（将来） |
| セッション | JWTストラテジー（Cookie保存）、有効期限付き |

## 5. 用語定義

| 用語 | 定義 |
|------|------|
| **テナント (Tenant)** | Office OS を利用する顧客組織 |
| **サービスカタログ (Service Catalog)** | 申請可能なサービスアイテムの集合 |
| **サービスアイテム (Service Item)** | カタログ内の1つの申請メニュー（例: PC購入申請、名刺発注） |
| **チケット (Ticket)** | 申請者がサービスアイテムを選んで作成する申請・依頼の単位 |
| **カスタムフィールド (Custom Field)** | サービスアイテムに紐づく動的な入力フォーム項目 |
| **エージェント (Agent)** | チケット処理・来客対応・ナレッジ管理を行う担当者 |
| **申請者 (Requester)** | カタログからサービスを申請する社内メンバー |
| **承認者 (Approver)** | 承認フローにおいて承認/却下を行う人 |
| **部署 (Department)** | テナント内の組織階層を構成する単位。上長自動解決に使用 |
| **機能グループ (TenantGroup)** | 公開範囲制御・権限管理に使用するグループ。ツリー構造サポート |
| **拠点 (Location)** | 物理的なオフィス所在地。来客管理・施設予約・フロアマップと連携 |
| **ナレッジ (Knowledge)** | FAQ・マニュアル・手順書などの社内ドキュメント |
| **RAG** | Retrieval-Augmented Generation。ナレッジを検索してAIが回答する仕組み |
| **SLA** | Service Level Agreement。チケットの解決期限の合意事項 |
